# Наблюдаемость фронтенда: демо для доклада

Учебный стенд к докладу «Серверных логов недостаточно, а клиентских у нас нет».
Vue 3 + Quasar + Cordova, пять слоёв наблюдаемости, каждый включается тумблером
прямо во время выступления.

Сюжет один: интерфейс молча ломается из-за рассогласования данных с бэкендом,
и по очереди действий пользователя этого не видно. Дальше слой за слоем
становится видно.

## Что внутри

```
collector/            коллектор, мок-API и дашборд — один процесс, ноль зависимостей
  server.mjs
  public/index.html   разбор сессий + воспроизведение записи (rrweb-player)
src/observability/    сами слои
  flags.js            тумблеры и конфиг
  session.js          идентификаторы, контекст устройства, вырезание ПДн
  breadcrumbs.js      хлебные крошки (ваша «очередь действий», но как контекст)
  errors.js           слой 0 — window/promise/resource/CSP/Vue
  network.js          слой 1 — fetch + XHR, тела ответов, traceparent
  contracts.js        слой 2 — валидация контракта API в рантайме
  replay.js           слой 3 — запись сессии в буферном режиме
  native.js           слой 4 — Cordova-контекст и детект аварийного завершения
  transport.js        слой 5 — очередь в IndexedDB, ретраи, дедупликация
src/pages/            каталог и корзина — здесь проявляется баг
src/components/DevPanel.vue   панель докладчика
docs/talk-outline.md          структура доклада с таймингом
docs/tools-comparison.md      self-hosted против платного — для слайда директору
```

## Запуск

Проект уже развёрнут как обычный Quasar-app-vite (Vue 3, Composition API) —
зависимости стоят, `src/boot/observability.js` подключён, Cordova/Android
режим добавлен (`src-cordova/`, платформа `android`). Один раз:

```bash
npm install
```

Коллектор (мок-API + дашборд, слушает `0.0.0.0:8787` — значит виден и с телефона):

```bash
npm run collector      # http://localhost:8787
```

Приложение в браузере — коллектор берётся из `.env` (`http://localhost:8787`):

```bash
npm run dev             # http://localhost:9000
```

### Сборка под Android

Для устройства нужен свой адрес коллектора — телефон не знает, что такое ваш
`localhost` (внутри WebView `localhost` — это само приложение, cordova-android
10+ отдаёт страницу с `https://localhost` через WebViewAssetLoader). Адрес на
момент сборки прописан в `.env.cordova` (`VITE_COLLECTOR_URL` / `VITE_API_URL`,
сейчас `192.168.1.114`) — это то, что подставится в приложение по умолчанию.

**Если на месте показа IP окажется другим — пересобирать не нужно.** В панели
докладчика (кнопка с жуком) есть поля «URL коллектора» и «URL API»: правите
прямо на сцене, изменение применяется сразу и переживает перезапуск приложения
(хранится в `localStorage` устройства). Кнопка «сбросить к значению из сборки»
возвращает то, что было в `.env.cordova`. Ради этого в `index.html` `connect-src`
для cordova/capacitor-сборки разрешает схему `http:` целиком, а не один
захардоженный адрес — CSP не умеет ни в CIDR, ни в wildcard по IP, а заново
применить более широкую политику из JS в рантайме уже нельзя, так что это
единственный вариант, который не сломается вместе со сменой сети. В обычной
браузерной сборке (`npm run dev`) CSP остаётся прежним, узким — туда эта
лазейка не протекает.

Совсем менять адрес в последний момент — по-прежнему можно и через
`.env.cordova` перед пересборкой, если время есть. Узнать актуальный IP:
`ipconfig` → IPv4-адрес нужного адаптера (не VPN).

Debug-APK (не требует подписи, ставится напрямую):

```bash
npx quasar build -m cordova -T android -d
# APK: dist/cordova/android/apk/debug/app-debug.apk
```

Установка на подключённый по USB телефон (включите на нём отладку по USB):

```bash
adb devices                          # телефон должен быть в списке
adb install -r dist/cordova/android/apk/debug/app-debug.apk
```

Живая пересборка на устройстве (для репетиции, а не для самого показа —
требует, чтобы телефон и ноутбук были в одной сети и держали соединение
весь сеанс):

```bash
npx quasar dev -m cordova -T android
```

**Брандмауэр Windows.** По умолчанию порты `8787` (коллектор) и `9000`
(dev-сервер) наружу не открыты — доклад начнётся с того, что телефон видит
пустой экран, а не с сюжета про NaN. Один раз, от администратора:

```powershell
New-NetFirewallRule -DisplayName "obs-demo collector (8787)" -Direction Inbound -Protocol TCP -LocalPort 8787 -Action Allow -Profile Any
New-NetFirewallRule -DisplayName "obs-demo quasar dev (9000)" -Direction Inbound -Protocol TCP -LocalPort 9000 -Action Allow -Profile Any
```

Перед докладом стоит один раз проверить с телефона (тот же Wi-Fi), что
`http://192.168.1.114:8787/api/products` вообще открывается в мобильном
браузере — это отсекает разом брандмауэр, гостевую изоляцию Wi-Fi точки
доступа и опечатку в IP, ещё до того, как в дело вступит сам стенд.

## Сценарий демонстрации

Порядок важен: каждый шаг должен оставлять зал в состоянии «и что теперь делать?».

1. **Все слои выключены.** В панели докладчика ставите бэкенд в режим «Типы».
   Открываете каталог, кладёте акционную куртку в корзину, жмёте «Оформить заказ».
   Пользователь видит: «Не удалось оформить заказ. Попробуйте позже.»
   В дашборде — пусто. Спросите зал, что случилось. Вариантов не будет.

2. **Включаете слой 0.** Ошибка появилась, но она бесполезная: сервер вернул 422.
   Мы знаем, что что-то не так, но не знаем почему.

3. **Включаете слой 1.** В таймлайне видно тело ответа `/api/products`:
   `"price": "12900.00"`, а `discount` в объекте вообще нет. Вот теперь понятно.
   Здесь же покажите `traceId` — тот же идентификатор напечатан в логах коллектора
   (`[api] GET /api/products trace=...`). Это стык клиента и сервера.

4. **Включаете слой 2.** Перезагружаете каталог: приложение сообщает о расхождении
   **до того**, как пользователь дошёл до корзины. В дашборде — событие `contract`
   с точным перечнем полей. Момент, ради которого доклад и делается: тихое
   расхождение перестало быть тихим.

5. **Включаете 2.5.** Данные чинятся на лету, интерфейс работает. Оговорка
   обязательна: это лейкопластырь, чинить надо контракт.

6. **Включаете слой 3**, повторяете сценарий, открываете запись в дашборде.
   Здесь же честно назовите цену: посмотрите на счётчик КБ в панели и
   расскажите про overhead на слабых устройствах.

7. **Слой 4** — сверните приложение и прибейте его из списка задач. При
   следующем запуске прилетит `session.unclean_shutdown`. Это единственный
   способ узнать про OOM-килл, не подключая нативный SDK.

Финал: включите режим «Хаос» и покажите, что при 502 и потере сети очередь
переживает перезапуск приложения — события долетают позже.

## Чего этот стенд намеренно не делает

- Не заменяет Sentry/GlitchTip. Это учебная модель, чтобы показать устройство
  изнутри. В прод берите готовое — см. `docs/tools-comparison.md`.
- Не собирает нативные краши. JS-слой их физически не видит.
- Не занимается симвоикацией стеков по source maps — это делает трекер.

## Три вещи, о которых стоит сказать вслух

**Персональные данные.** В записи сессии видно всё, что видит пользователь.
`maskAllInputs: true` включён по умолчанию, для блоков с ПДн есть классы
`obs-mask` и `obs-block`, тела запросов чистятся по списку ключей в
`config.redactKeys`. Проверьте этот список под свои проекты **до** включения
в проде, а не после. Хранение на своих серверах в этом свете — не только
экономия, но и упрощение истории с 152-ФЗ.

**CORS и preflight.** Заголовок `traceparent` — кастомный, значит браузер
сначала отправит OPTIONS. Бэкенд обязан вернуть его в
`Access-Control-Allow-Headers`, иначе слой 1 положит вам все запросы.
В `collector/server.mjs` это сделано, посмотрите функцию `cors()`.

**CSP.** Если в приложении настроен `Content-Security-Policy`, домен коллектора
нужно добавить в `connect-src`. Иначе события будут молча блокироваться —
и вы получите ровно ту ситуацию, от которой уходите.
